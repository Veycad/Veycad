# Контракт устройств и видео — development baseline 0.1.0

Этот документ отделяет техническую возможность установки от подтверждённой
работы рендера. Поддержка нового устройства или кодека подтверждается только
полным экспортом и просмотром MP4 на таком устройстве.

Для текущего development baseline подтверждены сборка и запуск на эмуляторе
Android API 36; отдельные полные экспорты на нём описаны в отчётах по стилям.
API 26–35 остаются целью совместимости APK, но не подтверждённой матрицей
полного пользовательского пути. Физический Samsung A25 проходил интеграционный
рендер на более раннем checkpoint; это свидетельство о движке, а не повторная
приёмка всех четырёх стилей текущей версии.

## Устройства

| Параметр | Текущий контракт |
| --- | --- |
| Android | API 26 (Android 8.0) — минимальная версия APK; сборка на API 36, target API 36. Полный путь на API 26–28 ещё не принят. |
| Архитектура | APK выпускаются для `arm64-v8a`, `armeabi-v7a` и универсальный. Основная цель проверки — физический ARM64. Наличие 32-битного APK пока не означает подтверждённое качество рендера на ARMv7. |
| Графика | OpenGL ES 2.0, EGL с recordable RGBA surface и поддержкой внешней OES-текстуры. Нужны работающие GLES-драйвер и H.264 MediaCodec encoder/decoder. |
| Аудио | Нужны локальное декодирование музыки и AAC-LC encoder; экспорт содержит AAC. |
| Память и место | Минимальный целевой профиль для beta: 4 ГБ RAM и 2 ГБ свободного места перед импортом. Текущая версия не проверяет эти пороги; нижний предел ещё требует прогона на физическом устройстве. API 36 эмулятор с ~2,5 ГБ RAM проходил отдельные регрессии, что не заменяет проверку ARM-телефона. |

Ближайшие обязательные проверки: физический ARM64 с 4 ГБ RAM, Android API 26/28,
нехватка места и слабые MediaCodec/GLES-конфигурации. Автоматический capability
planner пока консервативный, а не основанный на реальных возможностях телефона
([REV-022](../todo.md)).

## Вход и выход

| Параметр | Текущий контракт |
| --- | --- |
| Вход | Системный выбор `video/*`. После импорта файл должен содержать локально декодируемую видеодорожку. Явный whitelist контейнеров и кодеков пока отсутствует: совместимость зависит от MediaCodec конкретного устройства. |
| Подтверждённый базовый вход | MP4 с H.264/AVC, SDR, обычной ориентацией или метаданными поворота. Геометрия проверена для 16:9, 4:3, 1:1 и 9:16; цвет и качество не подтверждены на всех телефонах. |
| Длительность входа | Для Сигмы, Heartbeat и FEAR минимум 15 с; DUALITY требует два видео минимум по 6 с. Верхний предел и бюджет анализа пока не реализованы ([REV-012](../todo.md)). |
| Выход | MP4, H.264/AVC и AAC-LC; обычно 720×1280, опция 1080×1920, для FEAR квадрат 720×720 или 1080×1080. Автоматический монтаж обычно 18–22 с, DUALITY — 18,3 с. |
| HDR и HEVC | Отдельные источники HEVC анализировались на Samsung, но общий контракт HDR→SDR и цветовой регресс на разных устройствах не завершены. HDR не входит в подтверждённый базовый вход. |

Открытые ограничения и результаты прежних проверок находятся в
[todo.md](../todo.md), [приёмке P1](p1-acceptance-2026-09-16.md) и
[отчёте Samsung A25](reports/A25-System-Integration-2026-09-02.md).
