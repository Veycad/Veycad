`ac54e7a8a6ede438cd08e0ff0b6c5cce6fc556af62ecace9747b142bbb5190cb`.

Это **не засчитывается как успешный отрицательный тест**: материал заранее
размечен как интенсивное движение, а случай был проверкой возможности
экспорта на таком материале. Отказ требует визуального разбора движения
в исходнике и сопоставления с наблюдениями модели; по одному коду отказа
нельзя признать материал неподходящим или объявить ошибку классификатора.
Не переименовываем неожиданную блокировку в ожидаемый успешный отказ.
Порог/детектор не менялись. До исправлений на базе этого источника весь его
родитель должен быть выведен в calibration/pilot для следующей версии.

Неразрушающая диагностика существующего v4-кэша (без нового анализа кадров
и без изменения фиксации): `blind_v1_fear_fullbody_20260926.motion-cache.json`.
Кэш связан с исходником SHA-keyed именем, SHA-256 самого кэша
`9a7d9135b1367f33fd6d33784dff0d21ac9e6204d075ba3303beda576b731436`.
121 наблюдение / 61 semantic frame. При зафиксированном пороге 0.18
измерено 8 движущихся samples, максимальная серия — 2, поддерживающая
серия >=3 отсутствует. Camera peak 0.591092, subject peak 0.225635.
По этим **измеренным векторам** ни одно вступительное окно не может иметь
требуемую серию из трёх кадров: отказ согласуется с действующим критерием.
Это не независимое доказательство точности самих векторов. `subjectMotion`
идёт из `LumaMotionEstimator`, а не напрямую из плотного optical flow:
остаток яркостных изменений умножается на направление их взвешенного
центра. Симметричное/встречное движение может давать малый результирующий
вектор даже при изменяющихся пикселях; это гипотеза механизма недооценки,
не подтверждённая причина именно этого материала. Сопоставление с видео
и отдельный тест симметричного движения нужны до любого исправления.

non-finite/over-full-scale/plateau — 0. Но политика offline-gate разрешает
Android headroom-unknown только как единственную причину отказа; здесь
другие дефекты сохраняются, `resolved_unknowns=[]`. Человеческая форма
создана пустой и привязана к этому MP4; `machine_and_human_pass=false`.
Категория matrix `outcome=positive` означает проверку экспортированного
положительного сценария, а не положительный результат качества.
При исправлениях по этому случаю вся родительская съёмка выводится из
следующей финальной независимой серии. Пороги v1 не менялись.

## Ограничение покрытия отрицательной длительности DUALITY

В фиксации v1 нет исходника короче 6 с: самый короткий — 10.02 с.
`corpus_ready=true` подтверждает разнообразие корпуса, но не существование
материала для каждого отрицательного случая release matrix. Поэтому
отрицательную длительность DUALITY в этой серии закрыть нельзя.
Состав v1 не изменяется задним числом. Для следующей заранее фиксируемой
серии найден отдельный оригинальный короткий кандидат, не запускавшийся
в монтаже: Seagulls on Ontario Lake 02, подробности в source-candidates.

Пакет для человека: `docs/quality/visual-review-packet.md`. Первый экспорт
DUALITY записан в release matrix с полученной отрицательной человеческой оценкой.
Матрица пока показывает `verified_case_count=0`, `ready=false`.
Завершение автоматических проверок отдельного MP4 не заменяет приёмку
всего продукта или остальных трёх стилей.
