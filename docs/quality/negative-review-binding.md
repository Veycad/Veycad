# Привязка человеческой проверки отказа

27 сентября 2026: найден и закрыт ложноположительный путь в релизной матрице.
Раньше отрицательная проверка требовала только имя, дату и два подтверждения
человека. При этих четырёх полях запись, явно относившаяся к другому продукту,
исходнику, коду отказа и файлу результата, всё равно засчитывалась.
В воспроизведении SIGMA получил `verified_case_count=1`, хотя скопированный
review описывал FEAR. Общая матрица оставалась красной из-за остальных пробелов;
это не был доказанный полный проход релиза.

Теперь отрицательный review обязан точно содержать:

- `recipe` — продукт проверенного запуска;
- `source_sha256` — первый исходник;
- `secondary_source_sha256` — второй исходник DUALITY, либо явно `null` для остальных;
- `rejection_code` — конкретный отказ;
- `result_sha256` — SHA-256 всех байтов проверенного `.result`.

Матрица читает `.result` один раз. Хеш и разобранные UTF-8 поля получаются
из одного и того же массива байтов. Даже добавление диагностического поля
после проверки делает прежний review неподходящим. Для DUALITY порядок
первого и второго исходника существенен. Подтверждение другой пары, другого
порядка, другого продукта или сообщения не переносится.

Можно создать **только новую пустую форму**, не поставив человеческие оценки:

```powershell
python tools/quality_review_form.py --negative artifacts/quality/runs/case.mp4.result artifacts/quality/runs/case.negative.review.json
```

Имя и дата остаются пустыми, `material_case_confirmed` и `message_specific`
остаются `false`. Человек должен проверить материал и конкретное сообщение
этого запуска, затем самостоятельно заполнить форму. Генератор не изменяет
результат и не перезаписывает существующие review. Исходный `.mp4.result`
должен быть отказом по материалу без соответствующего MP4.

Исторические формы без этих привязок сохранены; текущая матрица не засчитывает
их как новые проверенные отрицательные случаи. Автоматически переносить
старые человеческие ответы в новые формы нельзя.

Проверки охватывают скопированный review, отсутствие или несовпадение каждого
поля привязки, изменение байтов результата, обратный порядок DUALITY,
незаполненную форму, неполный/ошибочный результат и защиту от перезаписи.
Положительная ветка сохраняет прежнюю привязку к выходному MP4 и независимое
повторное измерение аудио.

Это проверка целостности записей, **не цифровая подпись человека**, не доказательство
фактического просмотра, истинности описания исходника, независимости съёмки
или качества монтажа. Полный выпуск по-прежнему требует независимых
положительных прогонов каждого из четырёх продуктов и настоящей человеческой
приёмки.
