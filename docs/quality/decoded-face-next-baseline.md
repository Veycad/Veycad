# Свежесть лица в декодированном результате — следующий baseline

Это контракт следующей сборки после сохранённого baseline16. Он не меняет
архив baseline16, его APK, старые результаты, отзывы WhiteKing или два
пользовательских DUALITY. Для новой сборки нужны новые тесты, отдельный
неизменяемый архив и фактические проверки MP4. На момент этой правки сборка
Android и реальные экспорты ещё не проверены.

## Исправляемая ошибка

Прежний decoded QA мог переносить последнее найденное лицо до очередного
100-ms face clock. Дополнительные кадры FEAR/Heartbeat и кадр после смены
сцены получали положительную уверенность не из своих пикселей. Ошибка модели
также не должна трактоваться как успешное отсутствие лица.

Для каждого QA-кадра, в котором лицо ожидается и допускается его оценка,
RenderedVisualSampler запускает детектор на текущем декодированном изображении.
Сохраняемые `outputTimeUs`, `sourceIndex` и `clipIndex` относятся к этому
изображению/назначенному кадру плана, а не предыдущему результату детектора.
Метод: `decoded-face-exact-pts-v1`.

Обе требуемые QA-масштабные попытки должны завершиться успешно; если текущий
bitmap уже не больше малого масштаба, требуется одна попытка. Успешная пустая
детекция — измеренное `0`; ошибка/таймаут хотя бы одной попытки — `null`
(неизвестно). При успешных попытках сохраняется прежний максимум confidence.
Пороги лица и стилистические исключения переходов/вспышек не меняются.

DecodedFaceEvidence.isFreshFor требует точное совпадение фактического output PTS,
источника и клипа. Приёмка дополнительно требует совпадение измеренного confidence
с sample. Копия старого лица, даже при разнице всего 33 333 us или смене клипа на
том же PTS, не подходит. Production-tagged ожидаемый кадр с неизвестным лицом
отвергается (`face-evidence-unmeasured`), даже если общий флаг требования лица
не выставлен. Legacy synthetic fixtures без provenance не считаются production
доказательством; при `requireFaceEvidence=true` они тоже отвергаются.

## Фактический отчёт и независимая проверка

Golden сообщает обязательные поля:

- `face_evidence_method`;
- `face_expected_samples`, `face_measured_samples`, `face_unknown_samples`;
- `face_unknown_times_us`, `face_empty_samples`;
- `face_loss_samples`, `face_loss_times_us`, `face_loss_rate`.

Python gate требует свежих измерений для всех ожидаемых кадров, ноль неизвестных,
пустой список unknown PTS и хотя бы один ожидаемый кадр. Counts должны быть целыми
и непротиворечивыми; успешных пустых детекций не может быть больше потерь лица.
Lost PTS должны быть упорядоченными, уникальными, неотрицательными и находиться
внутри результата; их число совпадает с loss count. Rate совпадает с
loss count / expected count с допуском 1e-6 на Float представление. Стилистические
пределы неизменны: 0.05 для Sigma/Heartbeat, 0.18 для FEAR/DUALITY.

Заявленное `acceptance=true` или положительный отзыв не заменяют эти поля.
Старые результаты без нового контракта не проходят текущий gate; их не
дополняют выдуманными измерениями и не изменяют задним числом.

## Проверки и ограничения

Добавлены pure helper tests: другое время/источник/клип, успешный ноль,
неудача одного QA-масштаба и невалидный scalar; gate integration tests:
свежий контроль, устаревшее/отсутствующее/mismatched evidence, неизвестность
при optional face requirement, отличающийся measured-zero face loss.
Два Python test cases проверяют обязательность всех полей и противоречия
counts/rate/PTS. Полный набор Python QA после этой правки: 88 tests, OK.
Android tests и сборка ещё не запускались в рамках этой правки.

После интеграции root завершил полный Android test/build:464 теста в68 наборах,
ошибок/отказов/пропусков0. Все88 Python QA-тестов также повторно прошли.
Сборка включает отдельную камеру cache17; её SHA и заранее объявленные
калибровочные имена — в `independent-camera-evidence-v17.md`.
Реальный экспорт с этой свежей face-проверкой ещё не подтверждён.

Exact-PTS provenance доказывает свежесть измерения, но не точность детектора,
не идентичность человека, не читаемость жеста и не художественную уместность.
Измерения выполняются на QA-сэмплах, а не на всех кадрах вне обязательного
Heartbeat-tail участка. Нужны новая runtime-проверка и просмотр человеком
1x/0.5x; старое зелёное число не доказывает качество нового монтажа.
