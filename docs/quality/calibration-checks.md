# Контрольные прогоны на известных исходниках

Это проверки работоспособности движка после изменений, **не** независимая
приёмка и не замена просмотра человеком. MP4 и `.result` находятся только в
игнорируемом локальном `artifacts/quality/runs/`.

После усиления проверки контейнера 2026-09-26 описанные ниже старые `.result`
не содержат новых обязательных полей `container_issues` и `encoded_*`.
Фраза «только human review missing» относится к инспектору на момент прогона;
нынешняя проверка требует нового экспорта/отчёта и человеческой приёмки.
Старые результаты не переносились в релизную матрицу.

## 2026-09-26 — камерные MOV и консервативная проверка исходных PTS

В корпус добавлены два неизменённых MOV Mendeley PRNU v1, CC BY 4.0,
Zeno Geradts. SHA-256 совпадают с публичным API; метаданные Apple iPhone 6,
30.62/30.52 с, около 30/60 FPS, полный decode без ошибок. Обзор исходных
контактных листов показал flatfield без людей; положительная пригодность
ни для одного стиля не заявлена. Одна сессия считается одним родителем.

Новый `quality_source_timing.py` сохраняет оригинальную временную базу и
оценивает все packet PTS, без перекодирования. Одного различия соседних
интервалов недостаточно: проверяется совместимость всех пар с постоянным
периодом и округлением до одного тика. Первая экспериментальная классификация
IMG_0079 по одной несовместимости была слишком сильной: могла засчитать
малые нерегулярности clock/timestamp как содержательный VFR stress. Исправлен
консервативный результат — `unknown` при разбросе всего один тик; старый
`.timing.json` сохранён как история, authoritative — `.timing-v2.json`.
IMG_0078 совместим с CFR; IMG_0079 не засчитан как VFR.

62 Python quality-теста проходят. Проверка фактического корпуса:
14 holdout-кандидатов, один пилот, 11 входов >=15 с, ошибок целостности нет;
MOV покрыт, остаются VFR и фиксация набора. Прогоны монтажа на новых MOV не
выполнялись, визуальная приёмка человеком не подменена метаданными/декодированием.

## 2026-09-26 — целостность фиксации независимого набора

Устранён пробел процедуры: `state=sealed` без контрольной фиксации теперь
не проходит проверку корпуса. Новый `quality_holdout_seal.py` связывает
состав/метаданные материалов, текущие исходники/ресурсы/debug-конвейер,

Release matrix требует совпадения сборки каждого прогона с фиксацией и
даты человеческой приёмки после неё. Это не подпись, доказательство личности
рецензента или автоматическое обнаружение скрытой настройки.

Фактический запуск создания фиксации на текущем корпусе корректно отказал:
нет MOV и VFR; `artifacts/quality/sealed-holdout.json` не создан. Набор

используют синтетические файлы только как unit-fixtures, не как доказательство
