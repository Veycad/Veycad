# Подсчёт независимых родительских съёмок

До правки матрица использовала `parent_sha256`, а при его отсутствии —
`parent_source`. Два файла с одинаковым `parent_source` считались разными
съёмками, если хеш родителя был заполнен только у одного. Общий corpus gate
отдельно считал только имена родителей, поэтому одинаковый parent SHA под
разными именами также мог завысить независимое покрытие.

`quality_holdout.parent_identities` теперь объединяет точные совпадения
`parent_source`, `sha256` и `parent_sha256` в связанные группы. Цепочка
совпадений принадлежит одной группе; порядок строк манифеста не меняет её
идентификатор. Эти группы используются в корпусе, проверке раскрытия пилотов,
подсчёте положительных родителей/пар и проверке обоих порядков DUALITY.
Два производных файла одной родительской съёмки не дают положительную
DUALITY-пару. Отсутствие parent SHA больше не создаёт нового родителя.

Добавлены шесть регрессий: неодинаковое заполнение parent SHA; цепочка алиасов;
две производные DUALITY-пары; одна родительская съёмка внутри пары; разные
имена при одном parent SHA; транзитивное раскрытие через pilot. Все шесть
падали до правки. После неё полный runner выполнил248тестов без ошибок,
падений и пропусков. Отчёт:
`build/reports/python-tests-parent-identity-20260930.json`.
Положительный тест отдельного полного набора продолжает проходить.

Это изменение локальных проверяющих инструментов; сохранённый APK0.1.8
`35683fe6c277f5670ed3f39bca5c88c0759bd1aebd82e3a12e598d0e9b50eab4`
не менялся. Исторические манифесты, seal и результаты не переписывались.
Правило устанавливает согласованность объявленных связей; для доказательства
происхождения новой съёмки всё ещё нужны сведения владельца.
