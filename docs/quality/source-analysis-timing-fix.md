# Исправление анализа по фактическим video PTS

## Реализованное изменение

План полной выборки привязан к отсортированным реальным PTS выбранного
видеотрека. Хвостовые запросы выбирают последний реальный кадр один раз,
с его настоящей меткой: не создаётся наблюдение на несуществующем late PTS.
Провайдер возвращает фактические метки декодированных целей; анализатор
использует только соответствующие ARGB-кадры и их метки.

Последовательный декодер в полном анализе дополнительно проверяет точное
совпадение output PTS с индексом цели: пропущенный кадр внутри диапазона
не может стать более поздним кадром с ложной ранней меткой. Ошибка этого
прохода или отсутствие ARGB-кадра больше не переводят весь анализ на
`getScaledFrameAtTime` с потенциальным sync-only fallback.
Отказ остаётся ошибкой анализа, не успешной отрицательной приёмкой материала.

Кэш версии 5 отделяет фактические PTS от старых v4-наблюдений.
Старые файлы не удалены ради результата, но новая версия их не использует.
Opening refinement сохраняет существующий отдельный контракт/планирование.
Числовые пороги качества, музыка и продуктовые грамматики не изменены.
