# Source-analysis capabilities: candidate v20 / cache18

This is a runtime-cost isolation change, not a successful montage, independent
holdout evaluation, speed benchmark, or human acceptance. The frozen v19 APK
and its cache17 diagnostic contract are not changed by these source edits.
No source-motion or decoded MP4/AAC acceptance threshold is relaxed.

## Evidence for the scope

The current production consumers of `Observation.motionMeasurement` and
`cameraMeasurement` are `FearOpeningEvidence`, its `FearSourcePool` callers,
and FEAR-only golden opener reporting. Heartbeat, DUALITY, Sigma and shared
event ranking use the separate legacy camera/subject vectors, current face,
pose/gesture, mask, composition and pixel-quality evidence. Decoded-output
acceptance does not consume the typed source correspondence measurements.

`MediaFrameVisualAnalyzer` previously prepared a full-frame correspondence
plane and invoked `PersonMotionEvidence.assess` unconditionally for every
product. Its assessment supplies only the two typed measurements and motion
diagnostics; it does not author their other scalars or renderer attachments.
This makes correspondence an unnecessary cost for the current non-FEAR
consumers. The slow live v17 Heartbeat process is not interrupted or relabelled
as candidate v20 by this change.

## Explicit capabilities, not a hidden fast flag

`SourceAnalysisProfile` has stable cache tokens:

- `EDITORIAL_SEMANTICS`: `editorial-semantics-v1`.
- `EDITORIAL_WITH_CORRESPONDENCE`: `editorial-correspondence-v1`.

The product-owned `requiredFor(recipe)` mapping requests full correspondence
for FEAR and editorial semantics for Sigma, Heartbeat and both DUALITY sources.
Every analysis call must explicitly request a profile. Reference analysis and
motion/mask debug probes explicitly request the full profile. If a future
product gate starts consuming correspondence, its capability requirement
must change before that consumer is enabled.

Both profiles keep the same exact decoded PTS, complete decoded image,
fresh semantic inference on every observation, pose/gesture availability,
legacy luma camera/subject vectors, dense editorial flow, masks/depth/face,
occlusion, composition, source-quality ranking and attachments. Only
correspondence-plane preparation and the correspondence assessment are gated.
The FEAR branch still evaluates every observation, including first-frame,
failed semantic, unsupported camera/body and other unknown outcomes.

## Not requested is not a measured zero

`MediaFrameVisualAnalyzer.Result` requires its profile and completed-assessment
count. Editorial results require count0 and null typed body/camera fields;
diagnostics label this `NOT_REQUESTED`, with motion-count fields
`not_requested`, not a static-motion success or an inference failure.
Full-profile results require completed count equal to observation count.
Their measurements may all be unknown: the profile proves assessment coverage,
not support, physical accuracy or FEAR suitability. Existing FEAR unknown,
static, sustained-run, camera-support and whole-body-support rules are unchanged.

Before constructing product graphs, the production editor verifies the required
capability for primary and secondary analysis. A full profile can supply the
editorial capability, but editorial analysis cannot satisfy FEAR.

## Cache18: isolated keys and checked header

Mandatory API: `key(source, intervalUs, profile)`.
Filename: `v18-{profile.cacheToken}-{intervalUs}-{sourceSha256}.bin.gz`.
The same source bytes and cadence cannot share an editorial/full cache key.

Decompressed big-endian header layout:

1. Existing magic `0x56414E4C` (int32).
2. Version18 (int32).
3. Profile cache token (`DataOutputStream.writeUTF`, Java modified UTF).
4. Completed correspondence assessments (int32, 0..4000).
5. Existing durationUs (int64), semanticFrames/maskFrames/modelSuccesses/
   observationCount (four int32), then unchanged cache17 observation and
   attachment payloads.

`read(file, expectedProfile)` rejects unknown tokens, mismatched requested
profile, invalid completion coverage, editorial records carrying typed
measurements, older cache versions and trailing payload. `store` requires
the key/result profiles to agree before writing. No implicit cache17 migration,
capability inferred from nullable fields, or historical result backfill occurs.
Frozen old APKs continue to use their original schema; new diagnostics need
cache18 generated by their explicitly requested capability.

## Verification boundaries

New tests cover stable tokens/product requirements, separate keys, skipped
preparation and assessment callbacks, full completion count, cache header and
trailing-data failures, old-version refusal, a full all-unknown result that still
fails FEAR, and an editorial result unable to satisfy FEAR. Synthetic observation,
event and Sigma/Heartbeat/DUALITY graph comparisons remove only typed fields;
they do not assert fresh model inference or encoded MP4 byte equivalence.

No Gradle, device, model or corpus run was performed by the implementing agent.
The root must build/test, freeze candidate v20 and verify actual new exports and
runtime timing before claiming any improvement. Existing motion-ranking debt
outside the FEAR opener remains: skipping an unused measurement does not make
legacy luma vectors physically measured motion, or complete any product's
independent/human acceptance.
