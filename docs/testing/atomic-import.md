# Проверка атомарного импорта

Контракт: [спецификация](../superpowers/specs/2026-10-18-atomic-import-design.md)
и [план реализации](../superpowers/plans/2026-10-18-atomic-import.md).

Выбор исходников определяется `filesDir/source-draft/current.json`.
Пока он не переключён атомарно, новый набор не считается выбранным.
Preferences с подписями — зеркало совместимости. При неизвестном результате
фиксации приложение сохраняет оба набора и отключает рендер до подтверждения выбора.

## Локальные проверки

Нужны JDK 25, установленный SDK/NDK проекта, Python для baseline и отдельный
запущенный эмулятор API 36. `ANDROID_HOME` указывает на SDK. Основной checkout
с чужими изменениями не использовать.

```powershell
.\gradlew.bat clean baselineVerify
pwsh -NoProfile -File tools/run_ui_tests.ps1 -Serial emulator-5562 -AvdName AutoEditAtomic_API36
```

На CI по умолчанию используются `emulator-5556` / `AutoEditUi_API36`.
Локальный `5562` выделен этой задаче: `5556` оказался одновременно занят
другим чатом, который переустанавливал тот же test APK. Допустим отдельный
чётный порт ≥5556; runner проверяет точное имя AVD и API 36. Не запускать
параллельные установки или instrumentation для одного пакета на одном устройстве.

Полный UI-runner собирает и проверяет изолированные APK, выполняет все обычные
тесты и проверки permissions, затем запускает process-death gate.
Он отвергает failures, errors, skips, missing и duplicate test cases.
Существующий тест настоящего MP4 входит в обычный набор.

Для адресного JVM-прогона:

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests 'com.veycad.app.SourceDraft*Test' --tests com.veycad.app.MediaWorkDispatchTest
```

## Отдельный process-death gate

После установки актуального UI APK можно запустить только проверку перезапуска:

```powershell
pwsh -NoProfile -File tools/run_atomic_import_restart_tests.ps1 -Serial emulator-5562 -AvdName AutoEditAtomic_API36
```

Скрипт изменяет только `com.veycad.app.uitest` на проверенном AVD.
Он очищает данные этого test-пакета перед каждым сценарием. Пользовательский
`com.veycad.app` не устанавливается, не очищается и не останавливается.
Экспортируемая управляющая Activity существует исключительно в uiTest source set;
в production-манифесте её нет. Проверка не зависит от внешней галереи или сети.

Каждый сценарий создаёт четыре разных декодируемых синтетических AVC/MP4:
пару A длительностью 1/2 секунды и пару B длительностью 3/4 секунды.
Подготовка проходит через настоящий EditSession, provider и SourceDraftStore.

| Контрольная точка | Что уже на диске | Ожидание после force-stop и нового PID |
| --- | --- | --- |
| FILES_PREPARED | Оба финальных файла B готовы; музыка подготовлена; current ещё A | Целый набор A |
| MANIFEST_COMMITTED | Атомарная замена current уже завершилась; State/preferences/GC ещё не опубликованы | Целый набор B |

Сигнал этапа записывается с fsync после соответствующего дискового действия.
Worker затем блокируется; host подтверждает PID, выполняет настоящий force-stop,
проверяет исчезновение старого процесса и запускает новую MainActivity.
Host независимо читает манифест и байты выбранных файлов, сравнивает SHA-256,
длины, порядок и подписи с fixture, проверяет новый PID и enabled renderButton
в UI XML. Пересоздание Activity либо новый экземпляр store не заменяют этот gate.

## Доказательства и ограничения

Результаты полного прогона: `build/reports/ui-tests.json`.
Результаты двух перезапусков: `build/reports/ui-tests/atomic-import-restart.json`.
Архив каждого запуска в `build/reports/ui-tests/restart/<run-id>/` содержит
checkpoint/verdict, команды, UI XML, screenshot и выбранные синтетические MP4.
JVM XML находятся в `app/build/test-results/testDebugUnitTest/`.

Отсутствующая контрольная точка, неверный PID, несовпадение байтов или неготовый
экран дают ненулевой exit; неполный сценарий не считается PASS.
Повреждение ожидаемого hash в локальной копии host-скрипта должно приводить к FAIL;
исходный скрипт и правильные fixture после такой отрицательной проверки сохраняются.

Windows-проверка путей использует настоящий junction, потому что создание файловых
symlink требует отсутствующей привилегии. На Android отдельно проверяются настоящие
symlink исходника и root с сохранением внешних bytes; skips не подменяют эти проверки.

Доказательства относятся к исключениям и смерти процесса на API 36.
Они не доказывают сохранность при обесточивании накопителя, устойчивость к ручной
модификации файлов, поведение downgrade, физическое устройство или художественное
качество монтажа. Полный hash/decode многогигабайтных видео при запуске приложения
не добавлен; SHA-256 здесь применяется только к малым тестовым материалам.
