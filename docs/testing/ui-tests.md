# UI-автотесты Android

Набор содержит **46 инструментальных тестов в 9 классах**. Они запускают настоящую `MainActivity`, нажимают элементы интерфейса и проверяют видимое состояние, настройки, файлы и Android-интеграции. Это отдельный набор от JVM-тестов алгоритмов монтажа.

Последний полный прогон 28 сентября 2026 года на `AutoEditUi_API36` прошёл: **46/46 тестов**, 0 ошибок и пропусков. Сводка находится в `build/reports/ui-tests.json` (запуск `20260928-034128-292`), подробности — в XML обеих фаз. Результат каждого следующего запуска определяется его свежими отчётами; наличие собранного APK или успешный выход `adb` сами по себе не означают, что все тесты прошли.

## Что выполняется реально

`UiTestFixtureRule` создаёт небольшой корректный MP4 локально. Для разных исходников используются различимые файлы, поэтому проверки порядка и копирования сравнивают реальные байты. Внешний экран галереи/выбора документов заменяется заданным результатом через Espresso Intents. Дальше работает настоящий обработчик результата выбора и `EditSession.import`: чтение `content://`, копирование файлов, музыка из ресурсов, фоновые задачи и обновление интерфейса.

Выполняются реальные операции с настройками, черновиком, временной директорией, публикацией готового результата и локальной библиотекой. Предпросмотр использует настоящий `VideoView` и Android-декодер. Сохранение проверяет запись в `MediaStore`, завершённое состояние записи и содержимое файла; отправка — `ACTION_SEND`, MIME, разрешение на чтение и доступные байты `FileProvider`. Тест уведомления проверяет реально опубликованное уведомление. Системные разрешения нажимаются через UI Automator.

Только тяжёлый движок монтажа заменён управляемым `CapturingRenderEngine` в тестовом варианте приложения. Он принимает настоящий запрос, позволяет выдать стадии прогресса, завершить работу, сообщить ошибку или предупреждение качества и записывает корректный видеофайл в настоящий путь результата. Отмена проходит через проверку отмены запроса. Это делает ошибки, отмену и пересоздание воспроизводимыми, сохраняя настоящий код управления сессией и файлами.

Общий помощник ожидает конкретное состояние интерфейса/сессии с ограниченным временем ожидания. Он не подменяет готовность черновика прямой записью флагов. Подготовленные предыдущие результаты нужны отдельным тестам для проверки сохранности данных.

## Изолированный вариант приложения и устройство

Используется вариант `uiTest`:

- приложение: `com.veycad.app.uitest`;
- APK тестов: `com.veycad.app.uitest.test`;
- runner: `androidx.test.runner.AndroidJUnitRunner`;
- тестовая Application и поставщик файлов находятся только в `app/src/uiTest/`.

Правило тестов проверяет суффикс `.uitest` перед очисткой. Оно сбрасывает данные этой установки и удаляет из галереи только записи, принадлежащие тестовому пакету. Обычная установка `com.veycad.app` имеет отдельные данные.

Скрипт дополнительно проверяет serial, имя AVD, API, package в метаданных и самом APK, а также `targetPackage` instrumentation. Он принимает только отдельный эмулятор на чётном порту от 5556. Рабочие `emulator-5554` и AVD `Fear_API_36` исключены. По умолчанию используется **`AutoEditUi_API36` на `emulator-5556`**.

## Запуск на Windows

Нужны JDK Android Studio, Android SDK с emulator/platform-tools/build-tools, PowerShell 7 и отдельный AVD `AutoEditUi_API36` с образом Android API 36. AVD должен быть создан заранее, например через Device Manager Android Studio. Скрипт собирает и устанавливает APK, но сам эмулятор не запускает.

Из корня проекта, если тестовый эмулятор ещё не запущен:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$uiSdk = 'C:\Users\rexar\AppData\Local\Android\Sdk'
$uiAdb = Join-Path $uiSdk 'platform-tools\adb.exe'

Start-Process -FilePath (Join-Path $uiSdk 'emulator\emulator.exe') `
    -WindowStyle Hidden `
    -ArgumentList @('-avd', 'AutoEditUi_API36', '-port', '5556',
                    '-no-snapshot-load', '-no-snapshot-save')

& $uiAdb -s emulator-5556 wait-for-device
while ((& $uiAdb -s emulator-5556 shell getprop sys.boot_completed).Trim() -ne '1') {
    Start-Sleep -Seconds 1
}

pwsh -File tools/run_ui_tests.ps1 `
    -Serial emulator-5556 -AvdName AutoEditUi_API36 -SdkRoot $uiSdk
```

Пути JDK/SDK нужно заменить, если локальная установка отличается. Для уже запущенного и полностью загрузившегося тестового AVD достаточно последней команды. Без `-SdkRoot` скрипт ищет SDK в `ANDROID_HOME`, `ANDROID_SDK_ROOT`, затем `local.properties`.

Скрипт `tools/run_ui_tests.ps1`:

1. Проверяет, что выбран отдельный нужный AVD и API 36.
2. Собирает `:app:assembleUiTest` и `:app:assembleUiTestAndroidTest`, проверяет идентичность APK и устанавливает только тестовые пакеты.
3. До запуска instrumentation сбрасывает разрешения видео и уведомлений тестового пакета. Отзыв уже выданного разрешения из работающего тестового процесса может завершить этот процесс, поэтому подготовка вынесена на хост.
4. Запускает сначала 2 теста разрешений, затем остальные 44 теста. Перед каждой фазой удаляет только старый XML этой тестовой установки.
5. Получает XML от `UiXmlRunListener`, сохраняет логи и сопоставляет точные `класс#метод` с найденными `@Test` в исходниках.
6. Возвращает код 0 только при завершённых обеих фазах, полном наборе тестов, согласованных итогах XML и отсутствии ошибок, падений, пропусков, повторов или неожиданных тестов. Неполный запуск тоже считается ошибкой.

В текущем окружении AGP **9.1.1** задача `connectedUiTestAndroidTest` упала в фильтрации устройств с ошибкой, связанной с `ImmutableCollection`. Поэтому полный скрипт использует сборку через Gradle, затем прямой `adb shell am instrument` с XML-listener. Это зафиксированный обход сбоя конкретного пути запуска, а не подтверждение ошибки самих UI-тестов или универсальное утверждение о всех установках AGP.

## Отчёты и разбор сбоя

| Артефакт | Назначение |
| --- | --- |
| `build/reports/ui-tests.json` | Итог последнего запуска: `passed`, число тестов, устройство, идентификатор запуска, ошибка и итоги двух фаз. |
| `build/reports/ui-tests/permissions.xml` | Последний полученный XML фазы разрешений. |
| `build/reports/ui-tests/screens.xml` | Последний полученный XML остальных экранных тестов. |
| `build/reports/ui-tests/runs/<UTC-run-id>/permissions/` | Архив XML, `instrumentation.txt` и `logcat.txt` для фазы разрешений. |
| `build/reports/ui-tests/runs/<UTC-run-id>/screens/` | Такой же архив для экранов и переходов. |

Начинать разбор нужно с JSON: `passed` должен быть `true`, обе фазы — полными. Для текущих исходников ожидается 2 + 44 = 46 выполненных тестов. Скрипт вычисляет ожидаемые имена из исходников, поэтому при добавлении/удалении теста полнота не зависит от вручную заданного числа. При сбое до instrumentation XML может отсутствовать; итоговый JSON всё равно указывает неуспех. Старый успешный архив не является результатом нового запуска.

## Границы проверки

- **Устройство:** текущий полный runner рассчитан на API 36; системные селекторы разрешений проверяются только там. Матрица Android 26–35 и физические устройства не проверены этим прогоном. В частности, сохранение через legacy SAF/`ACTION_CREATE_DOCUMENT` на API 26–28 и старое разрешение `READ_EXTERNAL_STORAGE` остаются непроверенными.
- **Внешние приложения:** возвращаемые URI и отмена выбора контролируются тестом. Сам интерфейс галереи/поставщика документов и фактическая отправка видео в другое приложение не автоматизированы; проверяются запрос и доступ к передаваемому файлу.
- **Жизненный цикл:** есть `ActivityScenario.recreate()` и переходы между состояниями Activity для предпросмотра. В манифесте Activity обрабатывает изменение ориентации/размера через `configChanges`; пересоздание не равно проверке поворота экрана. Реальное уничтожение процесса ОС, холодный перезапуск после него, перезагрузка устройства и длительная работа в фоне не моделируются. Семантика пересоздания описана в [ActivityScenario](https://developer.android.com/reference/androidx/test/core/app/ActivityScenario).
- **Монтаж:** набор не подтверждает реальный рендер движком, работу ML/GLES, точность анализа, качество склеек, изображения и звука. Для алгоритмов нужны отдельные JVM/интеграционные проверки и реальные видео. Переданный размер/битрейт проверяются в запросе, но качество кодирования не оценивается, потому что результат здесь — подготовленный MP4.
- **Вид и скорость:** нет эталонных снимков/проверки пикселей, сравнения цветов и шрифтов, полного аудита доступности, проверки всех размеров экрана или измерения производительности. Проверка видимости и прокрутки кнопок не является полной проверкой оформления.
- **Уведомления:** проверяются системное разрешение, сохранённая настройка и публикация уведомления без повторов; все действия из системной панели уведомлений не покрыты.

В проекте закреплены `core-ktx`, `runner`, `rules` **1.7.0**, `ext:junit` **1.3.0**, `espresso-core` и `espresso-intents` **3.7.0**. Версии здесь описывают фактические зависимости проекта, а не автоматически обновляемый набор.

Основные первичные руководства: [Espresso](https://developer.android.com/training/testing/espresso), [UI Automator](https://developer.android.com/training/testing/other-components/ui-automator) и [ActivityScenario](https://developer.android.com/reference/androidx/test/core/app/ActivityScenario). Код использует API закреплённых версий; примеры новых версий документации требуют проверки совместимости перед переносом.
