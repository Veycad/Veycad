# Совместимость проверенного текстового модуля с одобренным сценарием

Это результат узкой сверки T1/T3/T5/T8, а не новая спецификация и не второй
редактор. Требования из `2026-10-10-text-subtitles-design.md` и согласованного
плана сохраняются. Реализация и исправления принадлежат PR #12; общая схема
ревизий — PR #15. Аудиокомпозиция этого потока продолжает T2 независимо.

## Проверенный вход сверки

Код PR #12 закреплён в локальном коммите
`a2e36bd60f756cf374673562d8323d71698fd474`. Документ владельца
`docs/integration/text-subtitles-contract.md` и протокол
`docs/testing/text-subtitles.md` опубликованы локальным коммитом `109b0c7a`.
Владелец сообщает 655 JVM, 255 Python и 12 уникальных feature-сценариев
эмулятора; здесь эти прогоны не повторялись и их артефакты не пересчитывались.
На момент сверки удалённая ветка ещё указывала на `be7dd23e`; интегратор
должен закрепить опубликованный reviewed SHA перед импортом.

Узкое чтение `TextEditProject.kt`, `TextLayerLayout.kt`, `TextEditSession.kt`
и `SpeechOutcome.kt` этого exact коммита обнаружило следующие различия.

| Требование принятого сценария | Фактический контракт a2e36bd6 | Необходимая совместимость у владельца |
| --- | --- | --- |
| Sans/serif/mono | `TextFont` содержит SANS/BOLD/SERIF | Добавить MONO, сохранив чтение и поведение старого BOLD |
| Фон none/dark/accent | `darkPlate: Boolean` даёт none/dark | Совместимое расширение оформления и сохранения для accent, без потери старых черновиков |
| Появление none/fade/slight scale до 200 ms, ограниченное интервалом | NONE/FADE/SLIDE; entrance делится на 250000 us | Добавить slight scale; выполнить заданные ограничения времени; не переименовывать молча старый SLIDE |
| Заголовок до 180 code points и трёх строк; субтитры до двух строк | Модель ограничивает `text.length <= 2000`; общий layout использует максимум две строки для любого слоя | Различить заголовок/субтитры в общем layout; проверить 180/181 code points, кириллицу, emoji и комбинируемые символы, сохраняя Unicode |
| Safe area x=.08.. .92, y=.10.. .85, читаемость и отсутствие перекрытий | Обычные позиции находятся внутри приблизительной области, но общий clamp разрешает y=.04.. .92 | Проверить фактические границы длинного текста и нескольких слоёв в 720p/1080p и квадратном FEAR; привести геометрию к принятой области |
| Настоящие границы слов; измеренные median <=200 ms, p95 <=500 ms | `SpeechTimingGranularity` содержит только PHRASE; `wordTimings=null`, `accuracyMeasured=false` | Расширить единственный backend/outcome реальными границами слов и измерить качество на размеченных RU-фикстурах; phrase PASS не закрывает word gate |
| Confidence ниже .75 либо неизвестная confidence явно требует проверки | `confidence=null`; `CaptionCue` не имеет review evidence, сессия сохраняет только cues | Сохранить и отобразить `needsReview` для неизвестной/низкой confidence через общий результат и общий проект, без выдуманного значения уверенности |

Начальный заголовок `[0,min(3 s,duration))` уже реализован `hook`; сохранять
его при расширениях. Различение Success/NoSpeech/Failure, отмена и borrowed
PCM API также уже существуют и должны переиспользоваться. Настоящий native
Whisper и успешная RU-фраза не заменяют измерение границ слов.

Эта сверка не утверждает дефекты непроверенных путей редактирования соседних
cues, рендерера или store. Полуоткрытые интервалы, отсутствие пересечений,
сохранение правок и последний MP4 остаются отдельными интеграционными
проверками уже согласованного плана.

## Порядок подключения

1. Владелец #12 публикует reviewed checkpoint, затем совместимые расширения
   собственных модели, сериализации, layout, редактора и STT outcome.
2. #15 сохраняет полное оформление и review evidence в общей ревизии без
   второго счётчика; прежние черновики/история остаются читаемыми.
3. Этот поток подключает подготовленный pre-music PCM к существующему
   `transcribePcmOutcome`; файл заимствован, освобождается владельцем
   композиции после завершения/отмены. MUSIC, SOURCE и SPEECH_AND_MUSIC
   связываются с общей ревизией и исходным звуком.
4. Exact-head проверки экспорта подтверждают видимость и границы текста,
   слышимую исходную речь и измеренные word timings. Эмуляторные проверки
   продолжаются; физический Samsung и человеческая приёмка отдельно.

До этих этапов модуль #12 является проверенным входом выбранного MP4 и
текстового редактора по протоколу владельца, а полный принятый сценарий
данного плана остаётся незавершённым. Требования не понижаются до имеющегося
phrase-only результата, и второй STT/backend не создаётся.
