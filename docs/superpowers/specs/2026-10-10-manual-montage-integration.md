## Checkpoint 4A: ручная политика рендера; 4B остаётся открытой

`MontageGraph.manualOverrides: ManualRenderOverrides? = null` содержит `disabledTransitionClipIds` и `disabledEffectIds`. No-op сохраняет null и исходный generator. Изменённый compiler выводит overrides из текущих descriptors и привязок, а не меняет рецепт. WHIP/impact nodes проверяются по originId и владельцу Clip; независимый flash/music не восстанавливается и не удаляется вместе с WHIP. Входящий переход переставленного первого клипа скрывается, но его payload остаётся enabled; исходная OPEN/входная авторская сцена сохраняется. При возвращении клипа на стык его узлы снова доступны.

`HighQualityFramePlan.Frame.transitionEffectsAllowed: Boolean = true` обязателен для TransitionTimeline и общего композитора при интеграции. При hard cut переходные blend/blur/offset и узлы WHIP выключены, WHIP-labelled translate/rotation обнуляются, scale/grade/независимые слои сохраняются. RenderPassPlanner видит те же effective transition/node/overlay значения. `EditableClipTiming.transitionPhaseDurationUs: Long? = null` — производная исходного descriptor в shared.original при неизменном типе, либо default нового типа. Подрезка использует исходный ClipPhase elapsed и этот знаменатель; видимая длина только ограничивает окно и не перезапускает фазу. Ручные tracks и envelope clocks сохраняют контракт задачи2.

`ManualMontageAcceptance.evaluate(graph, container, samples, decodedAudio, fps: Int): Report(passed, issues)` требует сохранённый FPS явно, включая no-op с editableTiming=null. Политика выбирается вызывающей стороной, а не наличием overrides. `RenderedMp4Acceptance.EvaluationPolicy.MANUAL_TECHNICAL` исключает автоматические beat/grammar/обязательные authored accents, сохраняя измеренные container/audio/face/mask/artifact проверки. Manual wrapper проверяет наличие декодированных samples каждого клипа, соответствие source/clip ожидаемому frame plan, длительность, включённый glitch и фактически сохранённые переходы. Это техническая проверка предоставленных свидетельств, а не доказательство происхождения декодированной текстуры или художественная приёмка.

Для каждого непрерывного сохранённого окна перехода minimum measured peak = `reference.minimumTransitionPeak × min(1, retainedOutputDurationUs / authoredPhaseDurationUs) × max(1 − abs(2 × retainedPhase − 1))`. Фаза и знаменатель берутся из исходного ClipPhase; одно кадровое окно учитывает длительность одного выходного кадра. Свидетельство должно иметь source/clip этого окна и outputTimeUs внутри того же интервала (допускается округление 1 мкс). Сила из другого клипа или за пределами окна не засчитывается. Положительный ожидаемый envelope не принимает нулевое измерение; endpoint с нулевым envelope, отключённые/дремлющие и полностью подрезанные переходы не требуют peak. Проверены WHIP/BLACKOUT, 30/60 FPS, граница 1201 мс и центральный фрагмент одного кадра (0 отклоняется, .02 проходит). Это согласованный эмпирический технический порог; native калибровка остаётся gate 4B/10.

Минимальный текущий adapter в MediaCodecSpeedRampRenderer выбирает temporal decoder по `secondarySourceIndex`, проверяет explicit `secondarySourceTimeUs` относительно длительности этого источника без clamp, передаёт secondaryAttachments в outgoing Frame и использует его sourceIndex для crop/rotation. `decodedAttachments(frame, actualPts, legacyTimeline, sourceAttachments)` выбирает timeline только внутри sourceIndex; непустая таблица запрещает fallback к чужим PTS. Глобальный clock используется для titles/absolute cues, originalOutputTimeUs — для исходной scene grade/Sigma entrance, outputTimeUs — для encoder PTS. `RenderedVisualSampler.sample(..., sourceFiles: List<File> = listOfNotNull(sourceFile), ...)` принимает явную таблицу файлов, выбирает retriever/crop по scheduled sourceIndex и использует фактический frame plan для переходов.

Общий `RenderQaSampling.targets` применяется к ручным и автоматическим графам. Он сохраняет обычный шаг QA (по умолчанию 100 мс), первый/последний кадры клипов и соседей границ эффектов/переходов, середину эффекта и постоянное число фазовых checkpoints перехода, включая matte-фазу .72–.80. Effective окна берутся через `TransitionTimeline.blendFor`/allowed flags, `renderNodes`, `renderOverlays` и `sampleWindow`: disabled/dormant/подрезанные cues не генерируются заново. В переходном окне до восьми retained кадров включаются все реальные frame-grid PTS и непосредственные соседи; 105ms BLACKOUT содержит четыре/семь кадров при30/60FPS. Длинные эффекты сохраняют ограниченное число landmarks и cadence; steady-shot ML работа растёт с длительностью/шагом, не с FPS.

Один фактический saved-FPS frame plan используется для target selection и decode; `RenderQaFrameIndex` связывает samples бинарным поиском O(log N), равное расстояние выбирает более ранний кадр. Автоматические raw legacy cadence и author anchors Reference accents/mirror/glitch, Heartbeat pulses/nodes/tail, FEAR author frame/scene/pulse объединяются с witnesses через sorted unique union. FEAR reference clock сохраняется без второго frame plan. Ручные overrides/editableTiming не запускают automatic author schedule. Decode tolerance ±1us и правило измерения каждого фактического Heartbeat tail изображения сохранены, включая запрет out-of-duration tail target. Численные acceptance thresholds, политики и source mapping не меняются; дополнительные samples могут выявить реальные QA failures.

Task4C исправляет только requested PTS. Native CUSTOM_MUSIC gate PR18 `143a478a` остаётся отрицательным: нужен отдельный exact-native rerun владельца музыки для восьми внутренних30fps PTS 1_533_333/1_566_667, 5_533_333/5_566_667, 9_533_333/9_566_667, 13_533_333/13_566_667us и соседей. Плановый cut label не доказывает actual transition execution: native renderer удерживает previous-source texture на первом generic overlap sample; DrawEvidence/source/clip/actualPTS provenance здесь не переписаны. Full4B held-frame/cross-source проверки, native latency, audio-headroom/colour-jump и художественная приёмка остаются отдельными gates. Renderer4dda и scoped-reset f51 не включены. Metadata-only owner transfer `b231b88` включён отдельным merge `c6d58fd`; app/docs blobs этого merge неизменны, shared16 production побайтно соответствует common95.

Текущий Heartbeat outgoing trail всё ещё использует первичный `uMask`/face pivot: отдельное `secondaryAttachments.mask`, refinement и face region ещё не загружаются и не потребляются этим shader path. ## Контракт модуля монтажа

- `EditableMontageProject` — внутренний адаптер над `HybridProject`, а не самостоятельный сохраняемый проект. Его исходники, исходная версия, текущая ревизия и номера выводятся из общего проекта. Параметры экспорта используют `ProjectExportSettings`, включая audio bitrate. Связь `CaptureLink` сохраняется на границе публикации.
- `EditableClip`, `MontageRevision`, signed `FrameRange` и `ClipTimeMapping` — значения проекции для монтажа. Публичный `ProjectAsset` модуля удаляется. Карта проекции строится из общего `SourceTimeMap` с каждой фактической точкой 0..N; разреженные карты материализуются по кадрам перед подрезкой. Оставшиеся PTS не меняются даже на 1 мкс. Границы source допускают конец durationUs, последний отображаемый sample строго меньше durationUs.
- `frameTimeUs` для неотрицательных кадров делегирует общему `ProjectClock`; signed кадры нужны только для проверки расширения окна. Экстраполяция за исходник отвергается; clamp не превращает ошибку в замороженный кадр.
- Сохраняемые дополнительные данные модуля — только привязки эффектов, local tracks и исходные координаты фазы/видимого окна. Они принадлежат графу конкретной `HybridRevision`. `MontageGraph.manualMontageState` — optional payload с default null. Адаптер проверяет ID, число видимых кадров относительно `span`, исходное число кадров фазы, идентичность исходника и допустимые PTS канонического `HybridClip.sourceMap`. Равенство текущей карты исходной не требуется: допустимый slip общего проекта сохраняется. Удержание PTS после trim проверяется в командах/importer, где разреженные карты сначала материализуются. ID и файлы в payload не становятся отдельным реестром.
- `MontageGraph.editableTiming` — производная покадровая проекция для общего `HighQualityFramePlan`. No-op импорт обязан совпадать с исходным планом, включая v1/v2, VFR, repeated PTS, authored tracks и разные sourceIndex. `globalOutputTimeUs` сохраняет глобальные часы при локальном PTS окна.
- `EditableMontageCompiler` подготавливает граф и timing для общего compiler/frame plan; он не сохраняет проект и не запускает директора. Рендер preview/export использует один общий snapshot.
- Чистые команды монтажа подготавливают изменение `HybridRevision`; назначение нового ID, undo/redo, CAS и сохранение выполняются общей точкой `HybridEditCommands.apply`. Совместимое расширение команд требуется до подключения UI; отдельная история модуля не создаётся.

## Минимальные расширения владельцу ядра

Проверенная часть common95 и оставшиеся общие gates:

1. Common95 предоставляет immutable selectedVideos: sourceIndex → selectionId/assetId, включая unused и repeated selections.2B1 потребляет таблицу без переиндексации. Передача фактических inspected selections общим factory остаётся отдельной интеграцией.
2. Сохранение optional `manualMontageState` и `editableTiming` в общем codec с сохранением исходных PTS, фаз эффектов и local tracks; round-trip сравнивается по frame plan. Старый проект без payload открывается без изменения расписания.
3. Common95 предоставляет CommitRevision/Undo/Redo с одним allocator/history;2B1 проверяет подготовленные обычные edits. Canonical scoped reset и общая CAS/store/factory граница остаются открытыми. Изменение music/text/framing не теряется.
4. Параметры исходного экспорта и CaptureLink на общей границе создания/публикации; source duration и playback geometry проверяются по контейнерам.
5. Compiler/analysis seam, который берёт attachments по asset ID/sourceIndex и source PTS; одинаковые PTS двух видео не смешивают маски.

До проверенного storage checkpoint задача 5 плана проверяет контракт и подготавливает интеграционные тесты, но не создаёт конкурирующие `EditableMontageProjectStore` или `EditableMontageProjectCodec`. Задачи 6–9 подключаются к проверенным общим factory/compiler/session/preview API. Нативная проверка и пользовательская приёмка остаются обязательными для готовности возможности.

## Подготовка графа задачи 2

`EditableMontageImporter.create(id, graph, recipe, export: ProjectExportSettings, sources, music, captureLink)` создаёт только значения общего проекта и адаптер. Индексы видео соответствуют порядку `sources`; asset ID, имена файлов, фактическая музыка и экспорт поступают от владельца factory. Начальная ревизия имеет ID 1, следующий общий ID — 2; самостоятельного allocator нет. Импорт принимает исходный winner без manual payload/timing, сохраняет v1/v2/v3 и не синтезирует отсутствующие tracks. Каждый исходный clip получает все scheduled PTS и exclusive endpoint.

`EditableMontageCompiler.compile(project, revision: HybridRevision = project.shared.current)` возвращает снимок `MontageGraph` для общего compiler; `layout(revision: MontageRevision, fps)` возвращает `ClipLayout(clipId, startFrame, endFrameExclusive)`. Чистая проекция `project.revisionView(revision)` принимает ещё не установленного кандидата с текущим ID: временный проект или новый ID для проверки не нужны. No-op сохраняет исходное миллисекундное расписание. Изменённая версия использует только канонический текущий `HybridClip.sourceMap` для source PTS. `HybridClip.original` текущей ревизии — единственный источник текущих `transitionIn`/`transitionDurationMs`; `shared.original` остаётся неизменным. Подготовитель команд меняет текущие descriptors, spans/source maps и `graph.manualMontageState`, сохраняя остальные music/text/style поля ревизии. Назначение ID, parent и истории выполняет общий `HybridEditCommands.apply(project, ProjectCommand.CommitRevision(candidate))`; store/CAS остаётся на общей границе.

Дополнительный `ClipPhase(firstFrame, startUs, durationUs)` в `ManualClipState`/`EditableClip`/`EditableClipTiming` сохраняет первый абсолютный номер исходного кадра, исходную границу клипа и исходную длительность. Это позволяет воспроизвести именно legacy `clipProgress`, включая границу 1201 ms, независимо от PTS и видимой длины. `visible.start` — signed смещение в исходной фазе. С checkpoint2B1 это значение выводится из общего `HybridClip.originalFrameOffset`; payload не является второй редактируемой истиной. Local tracks принадлежат клипу, но их keyframe timestamps остаются в исходном authored clock: sampler получает `ClipPhase.timeUs(originalFrame, fps)`. Их кривые не переписываются при подрезке. Timing и локальные keyframe/value lists копируются в неизменяемые снимки.

`MontageEffectBindings.bind(graph, fps)` явно относит `heartbeat-pulse-*`, `fear-step-*`, `onset-flash-*` и `reference-first-phrase-impact` к Music; transition nodes `whip-glow-*`, `whip-glitch-*`, `impact-glow-*` — к входящему Clip; обычный FLASH в пределах 100 ms от стыка — к Boundary; остальные пересечения — к локальным Clip-сегментам. Близость к биту не определяет Music. Boundary первого клипа сохраняется в payload, но не выводится в граф; возвращение клипа восстанавливает слой. Compiler не генерирует заново удалённые эффекты и не решает политику отключения WHIP bundle: подготовка явных enabled/payload изменений принадлежит задачам 3–4, самостоятельный flash независим.

Overlay/Node имеют `originId`, `phaseStart`, `phaseEnd` с legacy defaults. `EffectSampleWindow(startUs, endUs, offsetUs, authoredStartUs, authoredEndUs, frameShift?, fps?)` хранит точное окно и authored clock сегмента. Для local-сегментов `frameShift` пересчитывает абсолютный номер исходного кадра; простой постоянный сдвиг микросекунд меняет некоторые retained samples на 1 мкс. Heartbeat и Sigma специальные ветви читают `originId`, сегмент идентифицируется `id`. Общему codec нужно сохранить эти поля наряду с payload/timing.

`MontageGraph.sourceAttachments: List<SourceAttachments(sourceIndex, timeline)>` выбирает mask/depth/flow внутри конкретного источника. При непустой таблице отсутствующий sourceIndex не откатывается к общему PTS-only timeline. `HighQualityFramePlan.Frame` передаёт `secondarySourceIndex`, `secondaryAttachments`, `originalOutputTimeUs`; поиск temporal role ведётся в исходном clock. Если искомый кадр подрезан, скрывается слой, первичный PTS продолжает двигаться. Общий decoder/compiler ещё должен потребить secondary source identity и attachments; эта задача не подключает новый decoder backend.

Дополнительные ограничения владельцу ядра: текущий порядок VIDEO assets допускает разные файлы, но не заменяет стабильную таблицу `sourceIndex → selectionId/assetId` для повторных выборов одного deduplicated файла. В reviewed common95 `ProjectMusic.gain` и legacy AudioTrack допускают 0..2; importer сохраняет gain2 без clamp. Общий factory/audio round-trip остаётся отдельным gate. Это открытое ограничение совместимости, не ослабление требования сохранения музыки. Для trim→extend нелинейной карты (включая предварительный slip) задача 3 должна восстановить сохранённые точки из общей original/history: экстраполяция края текущей подрезанной карты не восстанавливает удалённые исходные samples.

## Чистая подготовка команд задачи 3A

`MontageTimelineEditor.prepare(project: EditableMontageProject, command: TimelineCommand): TimelinePreparation` возвращает `Prepared(candidate: HybridRevision, changedClipIds: Set<String>)`, `Unchanged` или `Rejected(reason: String)`. Кандидат сохраняет входные `id`/`parentId`; `compile(project, candidate)` проверяет и материализует его граф до возврата. Кандидат не устанавливается в `HybridProject`. Здесь нет `apply`, отдельного `MontageUndoHistory`, allocator, CAS или сохранения.2B1 behavioral tests передают обычный Prepared в настоящий общий CommitRevision и проверяют Undo/Redo. Full3B остаётся открытой до canonical scoped reset и persistence/raw-bounds/runtime gates; Unchanged/Rejected не меняют history/redo/nextRevisionId.

Trim принимает signed координату исходного выходного кадра. Сохранённые PTS внутри текущего окна остаются буквальными; для удалённых точек читаются общие undo-ревизии от новых к старым, затем original, без redo. Карта совместима только при совпадении источника, координат фазы и постоянного смещения PTS на всех общих плотных samples, включая exclusive endpoint. Новейшая покрывающая точку несовместимая карта вызывает отказ, а не подмену устаревшим baseline. Отсутствие восстановимых samples внутри исходного окна и неоднозначный trim без сохранённых координат также вызывают отказ. Никакого второго реестра сохранённых карт нет. Тесты включают внешне изменённую нелинейную карту в undo при отличающемся линейном original, repeated/sparse PTS и slip→trim→extend.

За пределами сохранённого материала продолжается край наиболее широкого совместимого сохранённого окна через общий SourceTimeMap с проверкой measured source duration; разреженный край сохраняет точную рациональную скорость. Уточнение численного примера плана: 9 кадров при30FPS и18 при60FPS — ровно0,3s выходного времени. Плотный округлённый край fixture даёт source endpoint3_299_997/3_300_006us, а sparse segment0..60 с1_000_000..3_000_000us даёт3_300_000us. Угадывать несохранённую идеальную скорость по FPS запрещено; оставшиеся samples не округляются повторно. Проверка source frames на native backend остаётся обязательной.

Move переносит прежние clip/source IDs и пересчитывает contiguous spans. SetTransition меняет текущий descriptor и только enabled существующих явно принадлежащих клипу WHIP/BLACKOUT nodes; не генерирует bundle и не возвращает перемещённые/удалённые flash. Полная политика и backend WHIP относятся к Task4. SetFlashEnabled принимает FLASH payload; MoveFlashToNext переносит только Boundary FLASH к следующему входящему clip, сохраняя ID, параметры и duration. Clip/Music anchors отклоняются без новой политики authored-clock переноса. Первый Boundary остаётся dormant в payload. RestoreBaseline восстанавливает ручные clips/maps/windows/transitions/effects из original, сохраняя текущие music/text/style/lockedCutIds. Если новое расположение нарушает ограничения locked cut или text span общего ядра, операция целиком отклоняется; поля не удаляются. Текущая музыка остаётся авторитетом общего compiler, а сохранённый graph.audioTrack не подменяет ProjectMusic.

Новые metadata/keyframe списки и descriptors кандидата принадлежат снимку. Это не означает владения вложенными семантическими массивами: в67e730cb sourceAttachments list копируется, но timeline и Plane.values сохраняют ссылки. Общий compiler/runtime PR15 должен предоставить bounded freeze либо lease в пределах32MiB analysis budget и регрессию с изменением producer collections/arrays для mask/depth/maskBlendTarget/flow. Этот обязательный integration gate открыт; второй semantic store или snapshot authority здесь не создаётся.

## Порядок и проверки

Реализация идёт последовательно агентами с отдельным ревью каждой части. Небольшие JVM-проверки запускаются с `--max-workers=1`. Полные локальные baseline/UI/native-прогоны и запуск эмулятора выполняются по очереди координатора; CI точного опубликованного коммита работает независимо. Чужие процессы не завершаются. Физическая проверка Samsung A25 и художественная приёмка не заменяются CI.
