# Причины отказа при подборе дубля: 0.1.16

Повторная обработка прежнего Samsung-исходника на локальном эмуляторе в 0.1.15 завершилась `insufficient_distinct_moments`, затем `capture_no_eligible_take`. На экране оставался общий отказ; конкретное пояснение было доступно только через «Эдиты» → съёмка → «Другой дубль». Это не подтверждает причину первоначальной ошибки пользователя.

В 0.1.16 штатный отказ подбора показывает номер и сохранённую причину каждой отклонённой попытки сразу в существующей карточке ошибки. Сообщение напоминает о сохранности записи и возможности вернуться к дублям. Типы диагностических ошибок, критерии пригодности, ручной выбор при неизвестной оценке, формат сохранённых оценок и исходные файлы не меняются.

## Регрессия и локальные проверки

`CaptureModeScreenTest#failedFullCaptureShowsItsTakeReasonWithoutOpeningLibraryAgain` создаёт настоящий полный 27-секундный AVC без человека, открывает его из библиотеки и запускает штатную нативную подготовку. До изменения тест завершился 1 failure: вместо конкретной причины было общее сообщение (`red-instrumentation.txt`). После изменения: **1/1 за 32.591 с** (`green-tests.xml`, `green-instrumentation.txt`). Проверены причина и номер дубля на основном экране, оба исходных типизированных отказа, отсутствие обращения к движку монтажа, неизменные байты съёмки/прежнего результата и READY-статус записи. Управляемый движок результата в этом тесте не вызывается; синтетический материал не служит проверкой качества человеческого эдита.

Чистый `gradlew.bat clean baselineVerify :app:assembleCameraPilot :app:assembleUiTest :app:assembleUiTestAndroidTest` прошёл за **3 мин 32 с**: **631 unit-тест / 81 suite, 255 Python-тестов**, без ошибок и пропусков; lint — 21 предупреждение, 0 ошибок. Сводка получена из фактических XML и лога. Полный Android UI для последнего опубликованного head проверяется отдельно в PR; локальный целевой тест не объявляется полным прогоном.

Universal и ARM64 cameraPilot **0.1.16 / code 17** проверены по подписи, манифесту, размеру и SHA-256 (`apk-016-manifest.json`). В APK присутствует обычная камера, отсутствуют тестовое приложение, управляемый движок и MP4. `build-inputs-016.json` связывает сборку с 266 входными файлами. Текстовые логи нормализованы в UTF-8/LF; исходные и нормализованные SHA находятся в `log-provenance.json`. APK и пользовательские видео в Git не входят.

## Samsung и пределы доказательств

5 октября Samsung Galaxy A25 (SM-A256E), Android 16 / API 36, снова подключён. CameraPilot обновлён с 0.1.14 до **0.1.15** без удаления данных; SHA установленной ARM64 APK совпал с ранее проверенной сборкой. Прежний 28966-мс FEAR-исходник сохранил SHA-256 и открылся через «Эдиты». Центрирование портретного превью проверено на экране телефона. Нативная повторная обработка этого дубля запущена на Samsung; её результат фиксируется отдельно после завершения. Это прежняя запись, не новая съёмка. Локальные данные находятся в ignored `artifacts/camera-samsung-015/`; снимки с человеком не публикуются.

AUTO-CAMERA-01 остаётся активной. Новая живая съёмка FEAR/Heartbeat, реальная синхронизация музыки, успешные нативные MP4 со звуком и художественная/визуальная приёмка владельцем ещё нужны. [Чек-лист устройства](../../../testing/auto-camera-device-review.md).
