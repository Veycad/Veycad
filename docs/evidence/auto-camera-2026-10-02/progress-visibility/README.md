# Видимый прогресс после съёмки: 0.1.14

Родительский commit `5dcd9583c37337f72bc42ea81aedf351969bc98b` прошёл GitHub Android baseline и Android UI (61/61). При дополнительной проверке штатной APK 0.1.13 обнаружен дефект UI: после полной записи обработка начиналась, но её карточка оставалась ниже видимой области экрана. На экране были только отключённые действия. `native-progress-hidden.png` показывает этот момент.

## Воспроизведение и исправление

Через обычный интерфейс `com.example.autoedit.camera` на выделенном API 36 (`emulator-5558`) записан полный синтетический Heartbeat MUSIC: 31979 мс, 2092157 байт, статус READY. Штатный анализ обработал 128 кадров за 22844 мс и отклонил дубль с `insufficient_human_evidence`; исходный файл сохранился с теми же байтами. Конечная ошибка видна в `native-material-rejected.png`, метаданные — в `native-heartbeat-before.json`. Это ожидаемая проверка ограничения материала, не готовый эдит и не съёмка человека.

Общий UI-регрессионный тест `new_operation_shows_progress_without_scrolling_and_updates_preserve_user_position` запускает настоящую сессию приложения с управляемым дорогим рендером. До изменения он завершился ошибкой ожидания видимого заголовка: `regression-before.txt`. Теперь появление нового задания показывает всю карточку прогресса после её layout. Дальнейшие обновления этапов не меняют позицию прокрутки, выбранную человеком. Используется существующая карточка и оформление приложения.

После исправления тот же тест прошёл за 3.716 с: заголовок и пояснение полностью находятся в видимой области; переход к следующему этапу сохраняет пользовательскую прокрутку; результат открывается. `regression-after.txt`, `targeted-after.xml`. Этот targeted-прогон выполнен с исправленным UI до повышения версии до 0.1.14.

Штатная universal APK 0.1.14 установлена на тот же выделенный эмулятор; SHA установленного `base.apk` совпадает с манифестом сборки. Через обычный UI выполнен полный FEAR MUSIC: READY, 26976 мс, 1803510 байт. Во время нативной проверки заголовок, пояснение и кнопка отмены целиком видны без ручной прокрутки: `native-progress-after.png`, границы элементов — в `native-fear-after.json`. После 20485 мс штатный анализ 108 кадров завершился отказом `insufficient_human_evidence` / `capture_no_eligible_take`. Источник остаётся на устройстве с размером из метаданных и зафиксированным SHA-256; конечное сообщение — `native-fear-rejected.png`. Это проверка видимости прогресса и отказа на синтетическом материале, не успешный нативный монтаж человека.
