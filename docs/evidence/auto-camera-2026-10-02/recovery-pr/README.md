# Checkpoint режима «Авто» 0.1.12

Цель AUTO-CAMERA-01 активна. Ошибка на телефоне пользователя пока не установлена: он сообщил о неудачной съёмке, но этап, текст, устройство и версия неизвестны. Проверки ниже относятся к конкретной ветке и эмулятору; физическая и художественная приёмка остаются открытыми.

## Источники и границы PR

Ветка `codex/auto-camera-recovery` создана от опубликованной `codex/commit-rules`, commit `6136a14317aa9746a2f056e53ba52b7e2797e0a7`. Этот base зависит от импорта проекта в PR #2 и правил в PR #3. `main` содержит только README; сравнение с ней до слияния зависимостей включило бы весь чужой импорт.

Камерный прототип перенесён по отдельному app-патчу `8dd643f8..7d8bb7e1` из прежней рабочей копии. Из общего рабочего каталога ничего не добавлялось автоматически. Сохранены уже опубликованные отступы системных панелей, исправление прокрутки кнопки сохранения и текущие Python-инструменты. Алгоритмы художественных стилей, ML-модели и инструменты качества взяты из опубликованной базы. Старые нативные пробы на пользовательских A/C не являются проверкой этой новой сборки.

Включены камера, сценарии и музыка FEAR/Heartbeat, хранение и выбор полного дубля, интеграция в существующие результат/библиотеку/настройки, локальная диагностика, нужные тесты и конфигурация эмулированных камер в UI workflow. APK, пользовательские видео, SDK-путь и локальные настройки исключены из Git.

## Воспроизведение и исправление

`regressions-before.txt` — терминальный прогон прежнего checkpoint 0.1.11. Он завершился тремя ошибками: две воспроизводят дефекты продукта, одна — неверный `scrollTo` в новом тесте фиксированной нижней кнопки.

1. Реальный `ProcessCameraProvider.unbindAll()` во время отсчёта оставлял сессию `PREPARING`, с нулевыми длительностью/байтами. Теперь старт ждёт поток превью; потеря камеры отменяет отсчёт без создания сессии. Повторное подключение позволяет записать MP4, который читает Android-декодер.
2. Просмотр FAILED-контейнера скрывал `session.error` и называл запись сохранённой. Теперь причины остановки и ошибки остаются видимы после неудачной проверки и пересоздания Activity; исходные байты сохраняются. Читаемый FAILED-контейнер после успешной проверки становится READY с теми же байтами и без прежней ошибки. Короткий проход по-прежнему недоступен для монтажа.
3. Для проверки нижней кнопки применяется обычный click; scrollTo остался для действий внутри ScrollView. `targeted-regressions-after.txt`: три сценария прошли до последней правки оформления ошибки. Последний полный UI-прогон также включает эти три сценария и проверяет заголовок ошибки и скрытое превью.

Визуальная проверка выявила оставшиеся после ошибки заголовок подготовки и последний кадр камеры. Последняя версия экрана показывает отдельный заголовок ошибки и действие повтора, убирает кадр и подсказки съёмки.

`camera-failed-container.png` и `camera-failed-recovery.png` используют намеренно невалидный тестовый файл из 512 байт и заданный текст ошибки кодировщика. Они не доказывают реальный сбой кодировщика на телефоне. Снимки других камерных сценариев используют синтетическое изображение эмулятора.

- Полный запуск `tools/run_ui_tests.ps1`, ID `20261002-083055-154`: **60/60 успешно**, 2 теста реальных разрешений и 58 тестов экранов/интеграции; без ошибок, пропусков, дубликатов и отсутствующих случаев. Результаты: `ui-tests.json`, отдельные `permissions-tests.xml`/`screens-tests.xml` и `ui-checks.txt`.
- После полного прогона изменён только test helper, который дожидается отрисовки снимка после пересоздания Activity. Повторный запуск трёх связанных сценариев прошёл: `screenshot-regressions-after.txt`, 21.351 с. Production-код и APK не изменились; снимки FAILED-сессии обновлены и просмотрены.
- Подписи APK проверены `apksigner verify --verbose`; пакет, версия и состав проверены отдельно. SHA-256/размеры — в `apk-*-manifest.json`. Инвентарь входных файлов сборки — `build-inputs.json`.
- Нативная APK имеет пакет `com.example.autoedit.camera`, версию `0.1.12-auto-camera-pilot`, code 13. Она использует обычный движок приложения; классов управляемого UI-движка и тестовых видео в APK нет.
- Universal APK установлена и запущена на выделенном `AutoCamera_API36`, `emulator-5558`. SHA установленного `base.apk` совпадает с файлом сборки. Проверены вход «Авто» → камера Heartbeat, работающий поток и доступная кнопка записи, оформление при шрифте 100%/130%. В этом smoke запись/монтаж не выполнялись. Данные: `native-smoke.json`, версия/установка и `native-heartbeat-camera*.png`.

Текстовые логи для Git нормализованы до LF с удалением хвостовых пробелов. Исходные локальные логи сохранены в ignored `artifacts`; содержание сообщений и терминальные результаты не менялись.

Сквозной нативный эдит с человеком, FEAR/Heartbeat MP4 со звуком, акустическая синхронизация, физические устройства и принятие дизайна владельцем не подтверждены. Пригодность материала и требования художественных рецептов не ослаблялись. [Приёмка телефона](../../../testing/auto-camera-device-review.md).
