# Проверка исправлений P1 — 2026-09-16

Область: REV-003, REV-009, REV-001, REV-002, REV-004 из `todo.md`. Проверяется текущая рабочая копия вместе с существовавшими изменениями FEAR/DUALITY; они не откатывались. Локальные видео и device-артефакты остаются в игнорируемом `artifacts/project-review-2026-09-16/`.

## Изменённое поведение

- Заданием владеет `EditSession` с application context и последовательным executor. Activity наблюдает LiveData и не удаляет job-файлы при уничтожении. Повторное открытие экрана подключается к выполняющейся работе.
- Отмена кооперативная: анализ, выдача кадров видео, AAC/mux и декодированный QA проверяют отмену. Изолированный matte-provider получает файл разрешения конкретного задания и проверяет его между кадрами. Текущий native-вызов должен вернуть управление; используемые файлы удаляются только после выхода worker. Вызовы provider сериализованы, чтобы старый/новый процесс не писали один общий временный кэш одновременно.
- Если Android завершит процесс, автоматического возобновления нет. При открытии приложение сообщает о прерывании, очищает scratch прежнего задания и восстанавливает исходники и последний опубликованный результат. Исчезновение файла разрешения останавливает дальнейший анализ старого задания в provider.
- Готовый MP4 публикуется через `.partial` → переименование в `files/completed-renders`. Метаданные summary/saved записываются отдельно атомарно; готовый MP4 восстанавливается и при отсутствии метаданных. Back меняет экран; «Создать новый монтаж» в idle очищает только draft. Последний несохранённый монтаж доступен в библиотеке, Share использует устойчивый FileProvider URI.
- Save получает неизменяемую запись конкретного результата. Занятое задание блокирует библиотеку, импорт, стиль, новый монтаж и повторный запуск. Save переживает закрытие Activity; локальная библиотечная копия появляется после атомарного переименования. Оба API-пути выполняют копирование в executor; legacy document picker сохраняет запись результата в instance state.
- Для каждого видеовхода определяется center-crop по display rotation и pixel aspect ratio. Входящая и исходящая текстуры имеют отдельные параметры. Авторский поворот камеры выполняется в пространстве пикселей выходного кадра. Маски/лица/flow/depth используют те же координаты источника; ожидаемые маски и исходная яркость QA проецируются через crop и камеру. Титр остаётся в координатах выходного кадра.

## Проверки

Среда: Android Emulator API 36, arm64, экран 1080×2400. `testDebugUnitTest lintDebug assembleDebug` завершились успешно. **252 теста, 0 failures/errors/skipped; lint 0 errors, 10 warnings.** Advisory для durable `commit()` и process-owned application context не скрывались; также остаются предупреждения picker/selected-photo access из отдельных карточек ревью.

Новые JVM-регрессы проверяют сохранность опубликованного результата после очистки scratch/draft, восстановление saved-метаданных, отказ публикации, разрыв между публикацией MP4 и метаданными; crop для четырёх форматов × четырёх поворотов × двух выходов, SAR, независимость двух источников, проекцию маски и положение/форму повёрнутой маски в портретном кадре.

**Device lifecycle:**

- Back уничтожает Activity во время монтажа → повторный запуск показывает выполняющееся задание, действия остаются заблокированы.
- Нажатие отключённой библиотеки не открывает сохранённый эдит и не даёт удалить используемые файлы.
- Явная отмена после повторного открытия возвращает idle; scratch пуст, SHA-256 исходников и прошлого готового MP4 не изменился.
- Холодный анализ проверен с временно перенесённым кэшем (после проверки кэш возвращён). Прерывание процесса во время анализа оставляет running-marker; новый процесс восстанавливает прежний сохранённый результат, сбрасывает busy и удаляет scratch.
- До финального прогона отдельно проверены Save → немедленный Back → завершение процесса → запуск: статус «Сохранено», одинаковый SHA-256 completed/library-копий, запись MediaStore `Movies/Veykad/`, размер 13 525 703 байта.

Локальный runner: `artifacts/project-review-2026-09-16/run-lifecycle.py`; снимки `p1-final-*.xml`, marker `p1-interrupted-prefs.xml`.

**Device geometry:** 24 реальных H.264/GLES рендера, 28 измеренных кадров. Открытые синтетические ролики: 16:9, 4:3, 1:1, 9:16; metadata rotation 0/90/180/270; выходы 360×640 и 360×360; авторские углы 15°, −15°, 33°; два источника 16:9/9:16 в обоих порядках с переключением как в DUALITY. ## Границы проверки и оставшийся долг

- Остановленный процесс восстанавливает безопасное состояние, не продолжает незавершённый рендер с того же кадра. Фоновый render не является foreground service: ОС может завершить его процесс.
- API 26/28 и медленный/облачный DocumentsProvider на устройстве не проверялись. REV-011 остаётся открытой до device-проверки, хотя копирование теперь асинхронное.
- Полная fault-injection матрица нехватки места/отказа provider/остановки на каждом проценте импорта и экспорта не выполнена; REV-005/010/019 и систематический androidTest/CI из REV-033 остаются открытыми.
- Полного визуального регресса всех художественных эффектов на физических устройствах нет. Синтетические проверки изолируют геометрию; SAR покрыт unit-тестом, не отдельным анаморфным MP4 на устройстве. Проблемы достоверности QA из REV-015/016 не закрываются исправлением координат.
- Опубликованные результаты намеренно не удаляются навигацией. Для накопления `completed-renders` нужна явная политика хранения/удаления и учёт дискового бюджета; сохранённые результаты имеют дополнительную private-копию.
