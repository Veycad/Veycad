## Причина и поведение

На API35/x86_64 с эмулируемыми страницами 16 КБ ручной экспорт останавливался
до кодирования видео. AAC-кодек принимал 48128 входных отсчётов, выдавал
47 пакетов и не выдавал два последних блока при EOS. При измеренной задержке
2048 отсчётов последний контрольный маркер терялся.

Калибровка теперь подаёт ограниченный запас тишины, измеряет автоматически
выданный хвост и при настоящем экспорте добавляет только недостающую часть.
Авторская длина PCM не меняется. Проверки всех трёх маркеров, точного числа
отсчётов, отрицательного начального PTS и метаданных не ослаблены.

Второе отличие API35: extractor сообщает длительность кодированного трека,
а не обрезанной презентации. Непрерывные часы AAC принимают только одну из
двух точно проверенных длительностей: по всем пересчитанным пакетам либо
по пакетам за вычетом настоящих delay/padding. Остальные проверки ASC,
непрерывных PTS, формата, числа PCM-отсчётов и конца потока сохранены.

Причина неудачного ручного экспорта теперь сохраняется в системном журнале
и локальной диагностике. Экспорт диагностики получает безопасные поля типов
исключений, а не текст ошибки с путями к файлам.

## Точность источников и ограничения

Native APK собраны до коммита; их точные хэши сохранены. Содержимое трёх
проверенных исходных файлов сопоставлено с коммитом с учётом нормализации
CRLF/LF Git; хэши рабочих и коммитных байтов записаны отдельно. Это не
подписанные релизные APK с подтверждённой установкой и обновлением.

Полный UI на последнем коммите, окончательные release APK и полная
устойчивость на 16 КБ ещё не приняты. Один ранний диагностический UI-прогон
завершился SIGSEGV в JIT-коде при ожидании неудачного экспорта; причина
не установлена. Последующие успешные группы не доказывают его устранение.

Существующая подготовка source/project AAC явно требует API35+. APK имеет
minSdk26: совместимость ручного экспорта на API26–34 остаётся отдельным
открытым релизным условием. Это исправление не снимает ограничение API.

## Проверка Android 9 / API28

Проверен существующий AVD `AutoEditAuditLegacy_API28`, Emulator37.2.13,
x86_64. Размер страницы 4096 подтверждён через `/proc/self/smaps`;
команды `getconf` в этом старом образе нет.

- Неизменённый APK #119: тот же native-тест завершается отказом SDK-ограничения
  за 0,166 с. Это отрицательная проверка совместимости.
- Изолированная диагностическая сборка с удалением только этого ограничения:
  FAIL за 0,875 с. Все проверки маркеров/длины/контейнера сохранены.
  `MediaMuxer.writeSampleData` выбрасывает `IllegalArgumentException` на
  отрицательном времени начального AAC-пакета. Исключение освобождения
  незавершённого muxer сохранено как suppressed.
- Это согласуется с [исходником Android 9 MediaMuxer](https://android.googlesource.com/platform/frameworks/base/+/android-9.0.0_r1/media/java/android/media/MediaMuxer.java#669):
  системный API отвергает отрицательные presentationTimeUs.

SDK-ограничение восстановлено; исходники чистые на `39ccf7e`. Проверочный
APK не является релизом и не включён в PR. На эмулятор возвращён исходный
проверенный APK с ограничением. Временная сборка внутри `app/build` может
оставаться диагностической: перед дальнейшей приёмкой пересобрать и сверить SHA.

Аудит `uiTestRuntimeClasspath` установил: CameraX1.6.2 уже приносит
Media3 muxer/common/container1.9.0. В официальных исходниках этой версии есть
`Mp4Muxer` и `MediaFormatUtil.createFormatFromMediaFormat`. Следующий шаг —
проверить совместимый MP4-путь на этой установленной библиотеке: немедленная
запись заимствованных буферов без batch/copy, точные duration/edit-list,
сохранение rotation и video PTS, затем декодирование на API28 и проверки
на API35/36. Наличие библиотеки само по себе совместимость не доказывает;
старый extractor тоже должен пройти прежние точные маркеры и число отсчётов.
