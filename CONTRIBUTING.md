# Работа через пул-реквесты

Изменения проекта готовим в отдельной ветке `codex/<краткое-название>` и
передаём на ревью через pull request. Один PR должен решать одну связную задачу.
Несвязанные изменения из рабочего каталога не включаем в PR автоматически.

1. Создайте ветку от актуальной основной ветки удалённого репозитория.
2. Внесите изменения и выполните подходящие проверки. Основной gate:
   `./gradlew clean baselineVerify` (Windows: `.\gradlew.bat clean baselineVerify`).
3. Отправьте ветку и откройте PR по шаблону. Если работа или приёмка ещё
   не завершены, откройте draft PR и перечислите оставшиеся шаги.
4. Проверьте diff и результаты CI для последнего коммита. Workflow
   `Android baseline` в локальном проекте настроен на событие `pull_request`;
   для запуска на GitHub нужно опубликовать исходники и workflow.
5. Сливайте только после явного одобрения владельца проекта и успешных
   обязательных проверок. После новых изменений нужно повторное ревью.

Для изменений монтажа успешного CI недостаточно: в PR укажите результаты
проверки экспортированного MP4 и состояние человеческой приёмки. Известные
ограничения должны оставаться видимыми в описании PR.

## Настройка удалённого репозитория

Удалённый репозиторий: https://github.com/rexarmakedonskij-hue/Veycad.
После публикации исходников и первого запуска CI настройте защиту основной ветки:
обязательный PR, одобрение ревью, сброс одобрения после новых коммитов,
обязательный успешный job `baseline` и разрешение обсуждений перед слиянием.
Точное имя проверки выберите по первому фактическому запуску CI.

Шаблон и этот документ задают порядок работы; принудительное соблюдение
обеспечивает защита ветки на GitHub, которую нужно настроить отдельно.
